# RDL Modules

**RDL_Modules** は、RDL Core の上で動く **T2 代謝機構層** のリポジトリである。

RDL Core が、RDL の基底仮設・最低動作仕様・基本代謝プロセスを保持するのに対し、RDL_Modules は、その代謝を実際に動かすための機構・操作群・補助ツールを育てる場所として扱う。

```text
T0 = 何を前提にするか
T1 = どう代謝するか
T2 = 代謝をどう実行するか
T3 = 外部対象へどう応用するか
```

---

## 位置づけ

T1 の基本プロセスは次の形をとる。

```text
SILN展開
↓
検査と選別
↓
再構成
```

T2 は、このプロセス自体を再定義しない。

T2 が扱うのは、

```text
T1 の各プロセスを実際にどう動かすか
```

である。

---

## 現在の核

現時点では、T2 の核を **耐久検査** として置く。

```text
仮設・構造を置く
↓
条件を変える
↓
破断を試みる
↓
どこで壊れるかを見る
↓
壊れても残る関係を抽出する
↓
再構成へ渡す
```

RDL 的には、耐久検査は次の運用に接続する。

```text
真理だから残す
ではなく
壊しても残った構造だから現在使う
```

現段階では、「耐久検査」と「破断検査」は別機構として分けず、同一の検査系として扱う。

## 現在の構成

```text
RDL_Modules/
├─ README.md
├─ 耐久検査/
│  ├─ README.md
│  ├─ 翻訳後の暫定ツール案/
│  ├─ 試運転/
│  └─ _暫定/
│     ├─ コア候補/
│     ├─ ツール候補/
│     ├─ 試行例候補/
│     ├─ 背景・思想/
│     └─ 旧版/
└─ 翻訳後の暫定操作案/
```

現在の `耐久検査/` は、移植直後のインキュベータである。

ここにある文書は、すべて暫定として扱う。

`翻訳後の暫定操作案/` には、耐久検査だけでは収まらない T2 操作候補を置く。
たとえば、検査済みの複数 SILN を比較・配置し、再構成へ渡す血肉化系候補などである。

```text
すべて暫定
↓
実際に使う
↓
使えたものだけ昇格
```

---

## 昇格原則

T2 モジュールの基本原則は、**使ってから昇格する** ことである。

```text
候補
↓
実運用
↓
入力・出力・破断条件を記録
↓
複数対象で再使用
↓
有効範囲を確認
↓
正式モジュールへ昇格
```

昇格候補には、少なくとも次の記録を求める。

```text
何を検査するか
B は何か
入力は何か
何を変化させるか
何を破断とするか
何が残ったか
どの範囲まで耐えたか
ξ として何を残すか
```

## T2 に置くもの

T2 に置くものは、大きく次の三種類である。

```text
Mechanisms
  T1代謝を直接実行する比較的明示的な機構

Operations / Toolkits
  自由度の高い操作群

Tools
  代謝操作を補助・整理・記録する道具
```

ただし、現時点では空の分類を先に作りすぎない。

実在する文書と実運用の蓄積を優先し、必要になった段階で分化させる。

---

## 将来候補

今後、実体が育った場合は、次のような構成へ整理できる。

```text
RDL_Modules/
├─ Mechanisms/
│  └─ 耐久検査/
├─ Operations/
│  └─ 展開操作群/
└─ Tools/
   ├─ 文書圧縮/
   └─ 階層モジュール/
```

展開操作群は、単一の正しい展開法ではなく、展開に詰まったとき自由度を増やす操作メニューとして育てる。

文書圧縮や階層モジュールは、T1代謝またはT2機構を実行・整理・記録しやすくする補助ツール候補として扱う。
